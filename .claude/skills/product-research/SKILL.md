# プロダクト開発前リサーチ ワークフロー

## 概要

「作るべきか・何を作るべきか」を判断するためのリサーチ。
**仮説を立てて調べる → 事実で検証する → Go/No-go を判断する** の順で進む。
感覚での開発着手を防ぎ、リソースを無駄にしない。

---

## Step 1: 問題仮説とスコープ定義

| 確認項目 | 例 |
|---|---|
| 作りたいもの | キャリア診断ツール / SNS管理ダッシュボード / LP制作サービス |
| 想定ターゲット | 転職検討中の20〜30代 / 中小企業のSNS担当者 |
| 解決したい課題（仮説） | 「転職の軸が整理できない」「SNS投稿が長続きしない」 |
| 調査の目的 | 市場の有無確認 / 競合との差別化発見 / 価格帯の把握 |
| 調査期間・深さ | クイック（半日）/ 標準（1〜2日）/ 深掘り（1週間） |

---

## Step 2: 競合分析

### 2-1. 競合の特定

**検索クエリ設計:**
```
直接競合: [解決する課題] + [手段] + [ツール/サービス]
間接競合: [ターゲットが今使っている代替手段]
site:crowdworks.jp / site:coconala.com + [キーワード]（クラウドソーシングでの競合確認）
```

**分類:**
- **直接競合**: 同じ課題を同じ手段で解決（3〜5社）
- **間接競合**: 異なる手段で同じ課題を解決（2社）
- **代替手段**: ツール不使用でターゲットが今やっていること

### 2-2. 競合マトリックス（2軸ポジショニング）

2軸の候補:
- 価格（高 ↔ 低）× 個別対応度（手厚い ↔ セルフサービス）
- 機能数（多 ↔ 少）× 専門特化度（特化型 ↔ 汎用型）
- ターゲット（プロ ↔ 初心者）× スピード（即時 ↔ 丁寧）

### 2-3. 機能比較表

主要機能10〜15項目を縦軸に、競合各社と自社案を横軸に並べる。
`○ / △ / ×` または `有/無/部分対応` で評価。
→ `assets/research-template.md` の競合比較表テンプレートを使用。

### 2-4. 差別化機会の抽出

競合が揃って弱い軸（コモディティでない領域）＝参入余地。
「全社が価格競争しているなら品質軸」「全社が高機能なら使いやすさ軸」。

## Step 3: ニーズ調査

### 3-1. 検索需要分析（定量）

**確認方法（WebSearch スニペットから推定）:**
```
"{キーワード} 悩み / 困っている"
"{キーワード} 解決策 / おすすめ"
"site:reddit.com / site:note.com {キーワード}"
"{キーワード} 相場 / 費用 / 料金"
```

**判断基準:**
- 検索スニペットに具体的な悩みが複数出現 → ニーズあり
- 解決策の情報が少ない / 古い → 市場が未成熟で機会あり
- 既存記事が充実 → 教育コストは低いが競合も多い

### 3-2. Jobs-to-be-Done（JTBD）分析

「ユーザーは機能を買うのではなく、課題解決のためにツールを雇う」

| JTBD の問い | 例（キャリア診断ツール） |
|---|---|
| いつ/どんな状況で使うか | 転職を考え始めたが何から手をつければいいか分からないとき |
| 何を達成しようとしているか | 「自分の市場価値」と「次の選択肢」を把握したい |
| 現在の代替手段は何か | 転職エージェントの無料面談 / 友人への相談 |
| 代替手段への不満は何か | 強引な求人紹介 / 恥ずかしくて本音が言えない |
| 理想のゴールは何か | 誰にも邪魔されず自分のペースで整理したい |

JTBDを言語化できると → コピーライティング・LP設計に直結する。

### 3-3. インタビュー設計（定性・必要な場合）

5人に聞くだけで主要な課題の70%は把握できる（Nielsen の法則）。

**聞くべき3点:**
1. **現在の困りごと**: 「〇〇をするときに一番大変なことは何ですか？」
2. **現在の解決策**: 「今はどうやって解決していますか？」
3. **満足度**: 「現在の方法の不満点は何ですか？」

⚠️ 「こんな機能があったら使いますか？」は聞かない（バイアスが入る）。

## Step 4: 市場規模・価格帯の見積

### 4-1. TAM / SAM / SOM

| 概念 | 定義 | 推定方法 |
|---|---|---|
| TAM（総市場） | 理論上の最大市場規模 | 公開統計 / 類似市場レポート |
| SAM（到達可能市場） | 自社がアプローチできる範囲 | ターゲット人数 × 想定単価 |
| SOM（現実的目標） | 3〜5年で取れるシェア | SAM × 市場シェア想定（1〜5%から）|

**ボトムアップ推定例（可能性ラボ）:**
- 転職検討者: 年間300万人（厚労省統計ベース）
- キャリア相談の有料化に抵抗がない層: 10〜15%
- SAM: 30〜45万人 × 月額3,000円 = 年間1,000億円規模
- SOM: 0.01%でも300人 = 月90万円

### 4-2. 価格帯リサーチ

競合10社の価格を集めて下記を確認:
- 最低価格・最高価格・中央値
- 価格帯ごとの機能レベル（どこで差がついているか）
- 「安すぎると信頼されない価格帯」の下限

---

## Step 5: Go/No-go 判定

### 判断基準チェックリスト

| 項目 | 判断基準 | 判定 |
|---|---|---|
| 市場の存在 | 検索・SNSでの悩み投稿が確認できる | ○/× |
| 市場規模 | SOM で月10万円以上が見込める | ○/× |
| 差別化の余地 | 競合の弱点か空白領域がある | ○/× |
| 実現可能性 | 1人・3ヶ月・予算XX万円以内で MVP が作れる | ○/× |
| 景表法リスク | 成果の断定表現を避けて販売できる | ○/× |
| 継続意欲 | 1年以上このテーマに関わり続けられる | ○/× |

**判定目安:**
- ○が5以上 → **Go**（進める）
- ○が3〜4 → **要条件変更**（ターゲット・価格・機能を絞り込んで再検討）
- ○が2以下 → **No-go**（別テーマを探す）

## Step 6: 出力形式

| 形式 | 用途 |
|---|---|
| リサーチメモ（Markdown） | 調査結果の一次記録・チーム共有 |
| 競合比較表 | ポジショニング判断・機能設計の起点 |
| エグゼクティブサマリー（A4 1枚相当） | 意思決定者への説明・自分の判断記録 |
| DocCraft ドキュメント | 提案・事業計画への組み込み |

## Gotchas（必読）

- ⚠️ WebFetch は 403 が多い → **WebSearch のスニペットから情報を読み取る**（environment.md 参照）
- ⚠️ 「競合がいない」は「ニーズがない」可能性が高い。競合ゼロなら検索ワードを変えて再確認
- ⚠️ 「使いたいと言った」≠「お金を払う」。インタビューの言葉より「今何にお金を払っているか」を重視
- ⚠️ 市場規模の数字は「意思決定の参考値」。精度より方向性（億円規模か億円未満か）の確認が目的
- ⚠️ Go/No-go は0か100かではない。「ターゲットを絞れば Go」「価格を下げれば Go」の条件付き判断も有効
