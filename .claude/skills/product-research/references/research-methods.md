# リサーチ手法リファレンス（プロダクト開発前調査）

## 競合分析フレームワーク

### Porter's 5 Forces（市場の魅力度判断）

業界・市場に参入する前の全体像把握に使う。詳細な競合分析の前段として。

| 力 | 問い | 可能性ラボでの例 |
|---|---|---|
| 新規参入の脅威 | 参入障壁は高いか | 国家資格がバリア（一定）|
| 代替品の脅威 | 他の手段に乗り換えられるか | 大手エージェントの無料化（高） |
| 買い手の交渉力 | 顧客が価格を下げさせられるか | 個人顧客・選択肢多い（高） |
| 売り手の交渉力 | 仕入先への依存度 | SNS・ツールの料金変動（中） |
| 競合他社の強さ | 既存プレイヤーの競争強度 | 参入者増加（高） |

→ 5つのうち「高」が3以上 = 参入難易度高い。差別化で対抗するか撤退を検討。

---

### 競合分析の4象限ポジショニングマップ

**軸の選び方:**
- 軸1: ターゲットの「最重視する要素」（価格・速さ・専門性・安心感 など）
- 軸2: 自社が差別化できそうな要素

**作成手順:**
1. 競合を横軸・縦軸上に配置
2. 密集ゾーン = レッドオーシャン
3. 空白ゾーン = ブルーオーシャン（ただしニーズがあるかは別途確認）

## ニーズ調査フレームワーク

### Jobs-to-be-Done（JTBD）の3層

| 層 | 内容 | 質問例 |
|---|---|---|
| Functional Job | 機能的にやりたいこと | 「転職先を探したい」 |
| Emotional Job | 感情的に得たいもの | 「不安を解消したい」「自信を持ちたい」 |
| Social Job | 社会的に見られたいイメージ | 「キャリアの選択を後悔しない人でいたい」 |

→ Emotional / Social Job に刺さるコピーのほうが購買動機を動かしやすい。

---

### カスタマーインタビューの5段階

1. **現在の行動確認**: 「今はどうやって〇〇していますか？」
2. **頻度・コスト確認**: 「それにどのくらい時間/お金をかけていますか？」
3. **不満の掘り下げ**: 「その方法で一番困ることは何ですか？」
4. **理想の確認**: 「理想的にはどうなってほしいですか？」
5. **過去の試行確認**: 「他の方法は試しましたか？なぜやめましたか？」

⚠️ 「こんな機能があったら使いますか？」は聞かない（YESバイアスが入る）。

### 検索需要分析（WebSearch スニペット活用）

WebFetch は403が多いため、検索スニペットから情報を読む手順:

```
# 課題・悩みの確認
"{テーマ} 悩み" / "{テーマ} 困っている"
"{テーマ} できない" / "{テーマ} うまくいかない"

# 解決策需要の確認
"{テーマ} 解決策" / "{テーマ} おすすめ"
"{テーマ} 比較" / "{テーマ} 選び方"

# 価格感の確認
"{テーマ} 料金" / "{テーマ} 相場"
"site:coconala.com {テーマ}" / "site:crowdworks.jp {テーマ}"

# 競合確認
"{テーマ} ツール" / "{テーマ} サービス"
"{テーマ} 2026" （最新情報の確認）
```

**スニペット読み取りのポイント:**
- タイトルと説明文に「悩み」「困っている」の具体例 → 顕在ニーズあり
- 「〇〇が分からない」形式の検索 → 教育コンテンツ需要あり
- 価格スニペットに幅がある → 価格競争中・差別化余地あり

## 市場規模推定手法

### ボトムアップ推定（おすすめ）

**公式:**
```
SAM = ターゲットセグメントの人数 × 購入率 × 平均単価 × 購入頻度
```

**手順:**
1. 公開統計でターゲット母数を確認（厚労省・総務省・業界団体レポート）
2. 購入率は類似サービスの転換率を参考（無料→有料: 5〜15%が目安）
3. 平均単価は競合の中央値から設定
4. 計算して「月XX万円のビジネスになりうる」と表現

**参照統計リソース（WebSearch可）:**
- 転職市場: `site:mhlw.go.jp 転職者数`
- SNS利用: `総務省 情報通信白書 SNS`
- 副業市場: `site:mhlw.go.jp 副業兼業`

---

### フェルミ推定（素早い市場規模の感覚確認）

例: 「個人向けキャリアコーチング市場」
- 日本の転職者数: 約360万人/年（約30万人/月）
- そのうちコーチングに興味ある層: 5%（= 1.5万人/月）
- 平均単価: 月2万円
- **市場規模概算: 3億円/月 = 年36億円**

→ 「億円規模か億円未満か」の方向性確認が主目的。細かい精度は不要。

## Go/No-go 判断の補足基準

### MVP（最小実行可能プロダクト）の設計

Go判断後の最初のステップ。できるだけ小さく始める:

| MVPの形 | 用途 | 例 |
|---|---|---|
| LP + 問い合わせフォーム | 需要テスト（作る前に売る） | 「開発中・先行登録」 |
| 手動オペレーション | 自動化前に人力で提供 | LINEで1対1返信 |
| 既存ツールの組み合わせ | 開発なしでサービス提供 | Notion + LINE + Googleフォーム |

**「MVP で10人に売れたら本開発に進む」が判断基準の目安。**

---

### ピボット判断基準

No-goでも完全撤退ではなく「条件を変えてGo」できる場合:

| 問題 | ピボット案 |
|---|---|
| 市場が小さい | ターゲットを絞って単価を上げる（ニッチ特化） |
| 競合が強い | 差別化軸を変える / アンダーサーブド層を狙う |
| 実現コストが高い | デジタル→アナログに戻す / 外注前提で設計 |
| 自分が続けられない | テーマを変える / 別の得意領域で同じ課題解決 |
