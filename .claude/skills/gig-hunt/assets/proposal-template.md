# 応募文・出品文・プロフィールの型

## 応募文（クラウドワークス / ランサーズ）

構成は5ブロック。**①は必ず案件固有**（ここがテンプレだと読まれずに落ちる）。

```
① 案件への言及（2〜3行）
   募集文の課題を自分のことばで言い換える。
   例:「投稿は作れているが保存・フォローにつながらない、という状態とお見受けしました」

② 提案（3ステップ）
   どう進めるかを工程で見せる。
   例: リサーチ（競合・トレンド）→ 構成案2パターン → 制作 + 公開前チェック（景表法対応）

③ 実績・根拠（数字とリンク）
   例: Next.js製のドキュメント作成アプリを個人開発（リンク）/
       キャリア系SNSの運用設計（リサーチ→企画→監査の体制構築）/
       LINE公式の導線設計（登録→面談の二段構えCTA設計）

④ 条件の明記
   納期 / 金額（税・手数料の扱い）/ 修正回数 / 連絡可能時間帯

⑤ 締めの質問（1つだけ）
   返信のきっかけを作る。
   例:「参考にされている競合アカウントはありますか？」
```

### NG集

- 「初心者ですが頑張ります」→ 不安材料の自己申告。書かない
- 実績の羅列だけで案件への言及なし → コピペと判断される
- 値下げの先出し →「ご予算に合わせます」ではなく金額根拠を示す

## 出品文（ココナラ）

```
タイトル: [検索キーワード]を含めて結果を約束しない形で
  例:「Instagram投稿の構成案＋キャプションを設計します」

▼こんな方へ（3つ・悩みのことばで）
▼提供内容（やること / やらないことを明確に）
▼料金プラン（松竹梅）
  ベーシック: [最小成果物]
  スタンダード: [+リサーチ・複数案]
  プレミアム: [+運用設計・継続]
▼納品までの流れ（ヒアリング → 初稿 → 修正◯回 → 納品）
▼よくある質問（修正回数 / 商用利用 / 秘密保持）
```

## プロフィール文（共通）

```
1行目: 肩書き（何を頼める人か一発で分かる）
  例:「SNS運用設計 × AI活用 × Web制作のフリーランス」
実績: 数字・成果物リンクを3つまで
対応範囲: できること / できないこと
稼働: 週◯時間・返信は◯時間以内
人柄: 仕事の進め方ポリシーを1行（例:「進捗は聞かれる前に報告します」）
```

## 実績の見せ方のヒント（このリポジトリの資産）

- DocCraft: Next.js + TypeScript の個人開発アプリ（スライド/ドキュメント生成、テスト321件）
- SNS運用: 週次リサーチ→企画→制作→景表法監査のワークフロー設計の実例
- LINE設計: 診断ファースト・ステップ配信（Day 0〜7）の導線設計の実例
- ポートフォリオとして見せる場合は、守秘情報（クライアント名・内部数値）を必ず外す
